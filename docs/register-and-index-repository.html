📌 Overview

This guide walks you through the complete lifecycle of registering a code repository and indexing it using the ProjectIQ API. The typical flow is:

REGISTERED → READY → INDEXING → INDEXED

All APIs are prefixed with http://:/api/v1. The examples in this guide assume the service is running at http://localhost:8080.

1 Register a Repository

Submit the filesystem path of the repository you want to index. The system will copy the repository into its managed workspace and generate a unique repositoryId (UUID).

POST /api/v1/repositories

Request Body

FieldTypeRequiredDescription
pathstringYesAbsolute filesystem path to the repository directory

📤 Example Request

curl -X POST http://localhost:8080/api/v1/repositories \ -H "Content-Type: application/json" \ -d '{"path":"C:\\Users\\parde\\Projects\\my-app"}'

For Unix-style paths:

curl -X POST http://localhost:8080/api/v1/repositories \ -H "Content-Type: application/json" \ -d '{"path":"/home/user/projects/my-app"}'

✅ Example Response (HTTP 201 Created)

{ "id": 1, "repositoryId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890", "repositoryName": "my-app", "originalPath": "/home/user/projects/my-app", "workspacePath": "/workspace/repo_a1b2c3d4", "registrationTimestamp": "2026-07-28T15:00:00", "lastUpdatedTimestamp": "2026-07-28T15:00:00", "lastRefreshTimestamp": null, "lastIndexingTimestamp": null, "status": "REGISTERED", "buildSystem": "Unknown", "technologyStack": "Unknown" }
💡 Note: The repositoryId (UUID) uniquely identifies the repository throughout its lifecycle. Save this value — you will need it for all subsequent operations.

6 Build Java Source Index (Full Index)

This is the core indexing step. It scans all Java source files in the repository and extracts structural metadata including packages, imports, classes, interfaces, enums, records, methods, constructors, fields, and annotations.

POST /api/v1/repositories/{repositoryId}/index
⚠️ Important: This operation can take time depending on the repository size. The repository must have been registered first (Step 1) and must have a valid workspace path.
ParameterTypeLocationDescription
repositoryIdstringPathThe UUID repository ID returned from registration

📤 Example Request

curl -X POST http://localhost:8080/api/v1/repositories/a1b2c3d4-e5f6-7890-abcd-ef1234567890/index

✅ Example Response (HTTP 200)

{ "status": "success", "message": "Java source index built successfully", "data": { "repositoryId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890", "indexedAt": "2026-07-28T15:05:00", "indexedFiles": [...], "statistics": { "totalJavaFiles": 42, "totalPackages": 8, "totalClasses": 15, "totalInterfaces": 3, "totalEnums": 2, "totalRecords": 1, "totalMethods": 120, "totalFields": 85, "totalAnnotations": 200 } } }
⚠️ Known Limitation: The POST /api/v1/repositories/{repositoryId}/index endpoint scans files and returns live counts in the response body, but the indexed data is not persisted to the database. Subsequent GET calls to retrieve indexing summary/statistics will return zero counts. To persist indexed data to the database, use the POST /api/v1/index/directory or POST /api/v1/index/files endpoints (shown below) which save results via indexRepository.saveIndexResult().

Use these alternative endpoints to persist indexed data to the database:

Index a Directory (Persists to DB)

POST /api/v1/index/directory?directory=/path/to/dir

📤 Example: Index a directory

curl -X POST "http://localhost:8080/api/v1/index/directory?directory=/home/user/projects/my-app/src"

✅ Response (HTTP 201 Created)

{ "status": "success", "message": "Directory indexed successfully: /home/user/projects/my-app/src" }

Index a Single File (Upload) — Persists to DB

POST /api/v1/index/files

📤 Example: Upload a Java file

curl -X POST http://localhost:8080/api/v1/index/files \ -F "file=@/path/to/MyClass.java" \ -F "filePath=com/example/MyClass.java"

✅ Response (HTTP 201 Created)

{ "status": "success", "message": "File indexed successfully" }

Index Multiple Files (Batch Upload) — Persists to DB

POST /api/v1/index/files/batch

📤 Example: Upload multiple Java files

curl -X POST http://localhost:8080/api/v1/index/files/batch \ -F "files=@/path/to/File1.java" \ -F "files=@/path/to/File2.java"

8 Incremental Re-Index

When files change, use incremental indexing to update only the modified files instead of re-indexing everything. This is significantly faster than a full re-index.

POST /api/v1/repositories/{repositoryId}/reindex/incremental
💡 Note: The controller maps {repositoryId} as a Long (internal ID). The service internally resolves it to the UUID repositoryId.

📤 Example Request

curl -X POST http://localhost:8080/api/v1/repositories/1/reindex/incremental

✅ Example Response (HTTP 200)

{ "status": "success", "message": "Incremental indexing completed successfully", "data": { "repositoryId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890", "filesAdded": 2, "filesModified": 5, "filesDeleted": 0, "filesRenamed": 1, "filesUnchanged": 34, "status": "COMPLETED", "startedAt": "2026-07-28T16:00:00", "completedAt": "2026-07-28T16:00:03" } }

You can also trigger incremental indexing directly via the Index API (uses UUID repositoryId):

POST /api/v1/repositories/{repositoryId}/incremental-index

📤 Example Request

curl -X POST http://localhost:8080/api/v1/repositories/a1b2c3d4-e5f6-7890-abcd-ef1234567890/incremental-index

Check Incremental Indexing Status

GET /api/v1/repositories/{repositoryId}/incremental-index/status

📤 Example Request

curl http://localhost:8080/api/v1/repositories/a1b2c3d4-e5f6-7890-abcd-ef1234567890/incremental-index/status

Full Re-Index

If you need to rebuild everything from scratch:

POST /api/v1/repositories/{repositoryId}/reindex

📤 Example Request

curl -X POST http://localhost:8080/api/v1/repositories/1/reindex
⚠️ Caution: Full re-index deletes all existing indexed data and rebuilds from scratch. Use incremental indexing when possible for efficiency.

10 Refresh Repository Metadata

Refresh the repository metadata to verify the workspace and update timestamps without re-indexing.

POST /api/v1/repositories/{repositoryId}/refresh

📤 Example Request

curl -X POST http://localhost:8080/api/v1/repositories/1/refresh

To update repository metadata (name, description, workspace path):

PUT /api/v1/repositories/{id}

📤 Example Request

11 Delete Repository (Cleanup)

When you no longer need a repository, delete it along with all its indexed data and workspace.

DELETE /api/v1/repositories/by-id/{repositoryId}
⚠️ Irreversible: This removes the repository registration, its workspace directory, and all indexed data. This action cannot be undone.

📤 Example Request

curl -X DELETE http://localhost:8080/api/v1/repositories/by-id/a1b2c3d4-e5f6-7890-abcd-ef1234567890

✅ Response (HTTP 204 No Content)

No body is returned on successful deletion.

📘 Appendix: Repository Lifecycle Status Flow

Repositories follow this lifecycle through their status values:

REGISTERED → READY → INDEXING → INDEXED
INDEXED → REFRESHING → INDEXED
Any status → FAILED
StatusDescription
REGISTEREDRepository has been registered but not yet processed or verified.
READYRepository workspace is verified and ready for indexing.
INDEXINGRepository is currently being indexed.
INDEXEDRepository has been successfully indexed.
FAILEDAn error occurred during registration, refresh, or indexing.
REFRESHINGRepository metadata or index is being refreshed.
